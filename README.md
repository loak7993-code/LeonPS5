# LeonPS5

A tool that ports PlayStation 5 executables to run natively on Linux, Windows and macOS. It converts a game's ELF into a native executable of the host and provides native builds of the PS5's system libraries that the converted program links against. There is no emulation and no separate runtime process: the converted game runs as a normal program on your machine.

A [relinker](core/relinker) converts the executable and its bundled modules to the target system's native format. Implementations of the [system prx libraries](core/libs/prx) provide the imports the converted program binds to at load time, each renamed to its NID so the OS loader resolves them without any patching.

> **Vibe coded.** This fork is developed end to end with an AI agent: the code, the tests and the docs. Every change ships with the 699-test suite green, the conventions checker clean and its unverified-on-console details documented in [Technical debt](docs/dev/TechnicalDebt.md).

## Features

- One command from game directory to running game: `leonps5 <game-directory-or-elf>` converts, assembles the runtime layout and launches.
- A [console-style home launcher](docs/user/launcher.md): scans a games directory, shows every title as a card and starts the runner with keyboard, mouse and gamepad control.
- The relinker targets Linux ELF, Windows PE and macOS Mach-O, with `--to-intel` lowering of AMD-only instructions.
- Every declared PS5 system-library function is either implemented or throws with a precise reason; the progress badges below are generated by this repository's own CI.
- The [shader recompiler](core/shader/recompiler/Recompiler.cpp) turns RDNA2 shader binaries into SPIR-V, with optional [Spirv-Tools](3rdparty/SPIRV-Tools) validation and optimization.
- Unknown and unexpected states strictly throw `std::runtime_error`; `what()` is printed to stderr and the process terminates. Nothing silently pretends to work.

## Quick start

Requirements: x86-64 host, Git, CMake 3.22 or newer, Ninja and a C++20 compiler. Linux needs the SDL X11 development headers (`libx11-dev` and `libxext-dev` on Debian and Ubuntu).

```sh
git clone https://github.com/loak7993-code/LeonPS5.git
cd LeonPS5
git submodule update --init --recursive

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel
cmake --build build --target libs --parallel

ctest --test-dir build
```

The `libs` target produces the patched system libraries in `build/core/libs/libs`; the runner picks them up from there automatically.

Then point the runner at a game directory that contains the game's ELF and its `sce_module/` modules:

```sh
./build/core/runner/leonps5 <game-directory-or-elf> [output-directory]
```

The command relinks the ELF, copies the system libraries and game resources into the runtime layout and starts the converted executable, printing its exit code. `--libs <dir>` overrides the system-library source and `--windows`/`--macos` prepare layouts for other hosts. The [relinker](build/core/relinker/relinker) stays available for direct use with every option documented in [Usage](docs/user/USAGE.md).

## Configuration

| Variable | Purpose | Default |
|---|---|---|
| `LEONPS5_GPU` | part of a Vulkan device name to run on, matched without case | first discrete-capable device |
| `LEONPS5_SYSTEM_FONTS` | directory holding the console font files for `sceFontOpenFontSet` | `leonps5-fonts/` beside the executable |
| `APS5_CAPTURE_TRACE` | start the GPU execution trace at first use | off |
| `APS5_PIPELINE_STATS` | print driver pipeline statistics per created pipeline | off |
| `APS5_ENABLE_TIMING_LOG` | write frame timings to `frame-timing.log` | off |

Input comes from SDL-mapped controllers, including analog sticks and triggers, and from a configurable keyboard and mouse mapping in `leonps5-input.ini`. See [input mapping](docs/user/INPUT_MAPPING.md).

## Build, test, deploy

- Build everything: `cmake --build build --parallel`.
- System libraries only: `cmake --build build --target libs --parallel`.
- Tests: `ctest --test-dir build`.
- Progress report: `python3 tools/progress.py out` writes the badges and progress map served by the Pages workflow.
- The runner alone: `cmake --build build --target leonps5 --parallel`.

Build switches, the relinker-only mode and the compiler details for Windows and macOS are documented in [Build instructions](docs/dev/BUILD.md). There is no install step: the build tree is the deployment.

## How it works

The [relinker](core/relinker) reads the PS5 ELF, resolves imports by NID, rewrites the dynamic section and emits a native executable; the [NID patcher](core/libs/nid) renames the system libraries' exports so the OS loader binds them by the same names. A converted game runs from this layout:

```text
app.elf
libs/   <- LeonPS5 system libraries (*.prx)
app0/   <- game resources and converted modules
```

The [shader recompiler](core/shader/recompiler/Recompiler.cpp) is isolated from the rest of the tree and is a pure function of its input, designed for reuse in other projects. The full data flow is drawn in [Architecture](docs/dev/ARCHITECTURE.md).

## Known limitations

- Signatures and error codes for functions never observed on real hardware come from reverse engineering references and are documented per file in [Technical debt](docs/dev/TechnicalDebt.md).
- A handful of AGC exports still throw because their console contracts could not be verified: `sceAgcGetDefaultCxStateFlat`, `sceAgcCbMemsetExclusive` (its embedded compute shader is not ported) and the `_0300` branch-patch targets.
- The runner is verified on Linux; the `--windows` and `--macos` paths prepare the layout and print the command to run it on that host.
- Console hardware verification of the remaining unverified-on-hardware notes is open work.

## Renamed configuration

This fork continues [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5) under its own name. Names changed accordingly: the runner binary is `leonps5`, runtime directories are `leonps5-out/` and `leonps5-fonts/`, the input mapping file is `leonps5-input.ini`, and the environment variables and CMake switches use the `LEONPS5_` prefix (`LEONPS5_GPU`, `LEONPS5_SYSTEM_FONTS`, `LEONPS5_RELINKER_ONLY`, `LEONPS5_ENABLE_SPIRV_TOOLS`). Internal ABI macros keep the upstream `APS5_` prefix (`APS5_VABI`, `APS5_EXPORT`) so upstream patch sets stay applicable.
